## 1. 提交候选与技术内容

本次收敛版本为 finalb1：完整 vllm-plugin-FL 与 FlagGems 源码在各自仓库内合并两个平台的改动。当前方案保留沐曦 Prefix B 与天数 formal4，不加入收益未证实的 Prefix C，也不加入 M64、采样器、量化、投机或新 Attention 探索。

沐曦 Prefix B 针对现有 MACA FlashAttention prefill 分支的整数前缀构造：原实现将设备张量转换为主机列表，再构建设备张量并归约；候选改用设备侧 new_zeros、cat 与 int32 cumsum。这里生成的是分段长度的累计偏移：P[0]=0、P[i]=sum(L[:i])，累加类型保持 int32，提示词前缀缓存策略保持默认。候选增加设备侧零向量、拼接临时张量及其启动成本；完整测试包含这些代价。原 Attention 数学、KV Cache 布局、decode/DCP/cascade 与后端选择均保留。

天数方案保留有界 KV 写入与 Decode Attention 融合、Graph 路由及数值稳定性处理。4K 支持上下文 4097-5119、指定 B32/B63/B64；16K 支持 16384-17407、指定 B1/B17-32。域外保持当前 FlagOS 路径。正式负载上的完整命中比例仍未知。

## 2. 本次合并包验收

本次合并包的结果与旧独立版本分开记录。所有安装文件与 wheel、交付源码逐字节核对；插件 213 个包内成员、FlagGems 2604 个。两次本地独立构建得到完全相同的 wheel 字节。

实际设备为沐曦 C500，双卡容器本轮使用 GPU1 单卡，不作为双卡并行成绩。栈为 vLLM 0.24.0+empty、PyTorch 2.8.0+metax3.7.0.7、Triton 3.0.0+metax3.7.0.7、MACA 3.7.0.38、EvalScope 1.11.1；cgroup 内存上限 96 GiB。模型与数据集八个文件均按锁定 SHA256 核验。

独立诊断使用 4105 token 输入进入真实 FlashAttentionImpl prefill 分支，记录 num_prefills=1。早先 19 token 诊断输入低于该后端 128 token 的 prefill 分界，因而未命中；相关失败日志保留。诊断插入的源文件见证在正式运行前移除，并重新核对完整包文件。该证据只证明路径可达，不代表正式运行命中比例。

本次合并包正式运行状态：completed。精度及性能数值以本报告表格和 acceptance.json 为准，缺失项不得用旧包成绩填充。

## 3. 测试口径与结果边界

精度为 Math-500 Level 3 全部 105 题，temperature=1.0、top_p=0.95、max_tokens=32768、batch=8；独立核对 105 个唯一题号、预测/评审配对、请求错误与准确率。判定下界 0.95，即至少 100/105；token 文本不同不直接等同正确性失败。

正式性能使用原 benchmark_throughput_serve.py，SHA256 为 0813eba574e9d1eb50c297c515baa426da1bcb61ce8c78a398b482f246005565。4K 为输入4096/输出1024/并发64/请求256；16K 为16384/1024/64/128。每场景四轮，首轮保留但不计汇总，第2-4轮求算术均值。

总吞吐同时包含输入与输出 token；表中 Mean TTFT 为原脚本口径。P99 汇总为逐轮 P99 的均值，不是合并请求后的分位数。当前结果不自动代表跨进程统计显著性，也不代表统一评审环境中的最终计分。

同机匹配默认前缀对照为103/105。本轮完整B包相对该对照：4K吞吐+19.01%、TTFT-35.17%；16K吞吐+16.61%、TTFT-19.05%。对照仅恢复原前缀构造和版本文件，其余合并框架及FlagGems相同；它不是纯上游仓库成绩，也不是官网参考分母。

测试顺序为完整B→完整A→同代码B的4K独立进程复验。该顺序有助于发现明显顺序漂移，但不是随机化的多次完整A/B试验；默认调优缓存、共享主机及运行时状态未全部控制。精度采用随机采样，102与103题的差别不足以单独建立数值退化结论，两者均通过正式0.95下界。

同包4K复验完整四轮完成，保留第2-4轮均值为5281.18总tokens/s、Mean TTFT 3098.20ms。没有修改代码、serve参数或请求规模；该项单独列出，不替换第一次完整验收，也不虚构第二次105题或16K结果。

4K复验吞吐较官网参考+3.76%、TTFT-3.16%，本次复验两项均在官网参考容差内；第一次完整4K与本次复验同时保留，不能只展示达标的一次。

官网沐曦吞吐参考4K为5089.645、16K为7029.675总tokens/s；Mean TTFT参考3199.435/27197.135ms。第一次合并包4K吞吐比参考低1.0273%，略超1%容差；16K吞吐高4.4845%，两场景TTFT均在容差内。不能把同机较低的默认前缀对照当作官网达标证明，最终认可仍由主办方统一复现评审决定。
