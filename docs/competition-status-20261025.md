## 3. 真正影响比赛决策的缺口

### P0：建立可提交候选与比赛验收之间的接口

1. 冻结明确的原版插件、FlagGems、模型、官方脚本与硬件版本，区分“官方原版”“共同数值修复”“性能候选”。天数预装tag与公开tag差异、最终认可commit仍需核对。
2. 冻结每项补丁的源码SHA、开关、资格条件与完整回退。运行期诊断单独进行，官方性能版本去掉影子计算和观察器。
3. 明确精度验证覆盖哪些优化分支；未命中的Math测试不能独立证明该分支正确。
4. 核对最新TTFT指标、完整阈值、16K脚本请求数与客户端隔离部署口径。官方页面本次抓取失败，不能称已经取得新规则确认。
5. 本次没有任何平台官方提交/验收的新结果；记录中的“通过”是本地实验门。

### P1：天数真正值得补的是2D/mixed路径

已保存证据表明：max query长度大于1时走2D，S8调整的3D分段不直接作用于该批次；低并发纯decode诊断又确实命中3D Graph。因此“完全没接上”与“所有Attention都被加速”都不成立。

待补的是代表性混合负载的实际Shape、阶段覆盖、完整2D开销，以及能够可靠获得的短窗口GPU活动。原Graph内部逐Kernel可靠耗时仍有工具缺口，但无需先把整个工具链修完才能选择下一条路线。

已有30分钟上限的离线采集协议；应先冻结脚本，再在用户明确授权的预约窗口运行。采集失败就保留unknown，不升级框架、延长工具维修或再跑数小时S8确认。

### P1：沐曦优先验证新的可消除开销，而非重复直写长测

prefix B是当前较有依据的新机会，但仍需来自科研侧的确定版本补丁、实际模型语义/执行模式支持和竞赛规则核查。比赛侧负责官方负载接入与最终验收，不同时在共享实例另写另一版B。若科研先做短模型研究验证，比赛可复用合格证据，正式成绩再按比赛合同验收。

旧高并发全程trace缺失不阻止规范端到端测试，也不值得为“数据齐全”继续空耗GPU。需要的是能影响实现选择的有界覆盖与成本数据。

## 4. 下一步顺序

1. **先离线准备比赛候选验收合同。** 为prefix B规定原版/候选身份、窄条件与回退、局部输出/KV、真实模型分支覆盖、Math-500、官方四轮及TTFT门。最终补丁通过单一版本移交，科研与比赛不重复改同一环境。
2. **天数准备30分钟2D/mixed诊断包。** 利用现有协议，采实际Shape与完整路径成本；优先识别新热点，不预约后直接重跑S8长测。
3. **只有新候选局部正确、实际模型命中、短回归无明显退化才跑完整bench。** 沐曦一次原版+候选完整4K/16K已有约90分钟服务时间的历史量级；实际需另留检查、精度、归档余量。正差再反序，不把短负载当正式成绩。天数16K单侧约3小时20分钟，两侧通常跨一个6小时窗口，先评估收益和预约连续性。
4. **冻结可提交版本。** 有稳定增益才默认开启；无收益回退原版，保留按场景/Shape合法选择的可能性。使用场景条件必须来自实际输入，保留框架主要派发与完整计算，不针对评测脚本取巧。

本轮不启动这些上机步骤。后续执行前按共享GPU协调文件核对实际租用与资源状态，不把历史关机、旧SSH或另一会话无owner字段视为现成空闲机器。
