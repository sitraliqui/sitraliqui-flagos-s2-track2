## 核心结论

存在可消除的开销，不能据此说默认实现已经没有空间。但在2048Token长查询块及近似大小的混合批次中，**简单的每次GPU内准备已经取得大部分收益，跨调用复用仅额外减少约1.1%—1.4%的完整Attention链耗时**。因此下一步应优先验证简单方案的真实模型收益，而不是直接将复杂缓存机制作为论文方法。

短查询边界中复用的额外收益更大。这提示输入计算规模、元数据准备频度和执行方式共同影响优化价值，但不能把正常的开销摊薄现象直接称作新规律或创新。

## 1. 实验对象与强对照

- A：实际安装版MetaX完整Attention.forward，原prefix通过GPU长度张量tolist、CPU列表、GPU tensor和cumsum准备。
- B：只替换这一表达式，使用GPU cat+cumsum；每次forward仍准备一次，无跨调用缓存。
- C：使用已有有限epoch实现，一次GPU准备，最多42次复用，计入prepare、有效性检查及close。

每个场景有42份独立构造的Q/K/V及KV缓存，一套共享元数据/页表；保持实际后端BF16、Q16/KV2头、head_dim128、page16。仍是同一个impl的42次完整调用，不是真实模型42层；原生Attention、KV写入和所有必要forward步骤均保留。

三组未改动模型、量化、官方benchmark或安装源码。采用过程私有的表达式改写，源码不匹配时拒绝执行。

## 5. 对研究意义的实际影响

### 可以据此继续的部分

这是一个真实源码中可消除冗余的性能见证，不只是想象空间。受控完整Attention链中简单方案B稳定优于原版，较大计算块中也有差距，因此值得进入可回滚模型接入及无观察器回归。

### 目前还不能当作贡献的部分

这不是新缓存理论，也不是新自动调优算法；不等于MiniCPM吞吐提升。C在较大查询块仅比B多约1%，生产scope开销有可能抵消这部分优势。仅以“缓存复用一次”写成方法贡献仍然偏弱。

值得继续检验的问题应收窄为：在真实模型不同prefill/mixed规模下，元数据准备方式造成多少可消除成本；GPU内逐次准备与受控复用分别在什么条件下值得采用。若结果只是一个后端修复，应定位为工程贡献，不能通过改称“小论文”跳过相关工作和有效性要求。

## 6. 下一步顺序

1. 优先把B做成最小可回滚模型改动，保留原分派、Attention计算和不支持模式回退；比引入跨层状态更容易核验。
2. 先做同输入局部数值、完整KV及模型短回归，独立记录原版A/A数值复现，不以原版selected-logprob零差失败直接否决B，也不据此任意放宽精度标准。
3. 关闭诊断后做原版/B交错的模型性能与官方精度验证。B没有可靠模型收益时先解释执行覆盖和端到端开销，不直接追加复杂缓存。
4. C仅在真实短prefill等有价值的工作负载上继续，必须包含生产scope管理成本并与B比较；不能只与A比较。

本轮到成本见证和关机归档结束，尚未执行以上模型晋级步骤，没有新模型吞吐或比赛成绩。成果可写入前期工程基础；论文可发表性尚不能由这些结果保证。
